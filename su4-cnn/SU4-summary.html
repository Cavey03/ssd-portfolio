Where CNNs are used

CNNs suit grid-shaped data where the same pattern can appear anywhere: images first, but also spectrograms, video, medical scans, and 1-D signals such as audio or text.

Ch 10 · p 177–179, 185

Trask introduces CNNs for image recognition (MNIST digits): first learn edges and corners, then the shapes built from them. Ch 10 · p 177–179

The key property is reusing weights. You need the same knowledge (what a line looks like) in every part of the image. Sharing one small set of weights across all positions means the network learns it once, has far fewer parameters, and overfits less. Ch 10 · p 178, 185

The convolutional layer

Instead of one big layer connecting every pixel to every output, a convolutional layer slides many small kernels (e.g. 3×3) over the image, making a prediction at every position.

Ch 10 · p 179–184

A convolutional kernel is a tiny linear layer: usually fewer than 25 inputs and one output. It predicts at one position, moves one pixel to the right, predicts again, and so on across and down the image. Ch 10 · p 179

The result is a smaller grid of predictions: an 8×8 image with a 3×3 kernel gives 6×6. A layer usually has many kernels, each learning a different feature; one fires on horizontal lines, another on diagonals. Ch 10 · p 179–180

output size = input size − kernel size + 1    (8 − 3 + 1 = 6)

In NumPy, Trask cuts every kernel-sized patch out of the images, stacks the patches, and multiplies them all by the kernel weights in one dot product: the same weights reused at every position. Ch 10 · p 181–184

Not in Trask

Terms you'll see elsewhere: stride (how many pixels the kernel moves each step; stride 2 halves the output), padding (a border of zeros so the output keeps the input's size), and channels (a colour image has 3 input channels; a layer with 16 kernels outputs 16 feature maps).

output = (input − kernel + 2 × padding) / stride + 1

conv = nn.Conv2d(in_channels=1, out_channels=16, kernel_size=3, padding=1)   # 16 kernels, 3x3

Pl

The pooling layer

Pooling combines several values into one, usually the maximum. It keeps the strongest signals and shrinks the data.

Ch 10 · p 180

In Trask's example, four 3×3 kernels each produce a 6×6 grid for the same image. Pooling combines them into one 6×6 grid: sum pooling adds them, mean pooling averages them, and max pooling keeps the largest value at each position. Max pooling is the most popular. Ch 10 · p 180

Not in Trask

In most CNNs, pooling is applied across space within each feature map: a 2×2 window with stride 2 keeps only the largest value in each 2×2 block, halving the height and width.

  • Less data: less computation and fewer weights in later layers
  • Small shifts don't matter (translation invariance): if a feature moves a pixel, the maximum often stays the same
  • Wider view: each later kernel covers a bigger part of the original image
  • Nothing to learn: pooling has no weights

A typical CNN repeats conv → relu → pool, then flattens the result into ordinary dense layers for the final classification. In PyTorch: nn.MaxPool2d(2).

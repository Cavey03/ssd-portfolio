SU5–7 · 5.1

Recognise the difference between using labelled and unlabelled data

5.1Trask+
Lb

Labelled vs unlabelled

Labelled data comes with the right answer for each example (image + 'cat'). Unlabelled data is just the raw examples. Labels make supervised learning possible but are expensive to get.

Ch 2 · p 12–13Ch 11 · p 190–191, 201

Supervised learning needs two datasets: the inputs and the matching outputs, which are the labels. Unsupervised learning has only inputs and no right answer to copy. Ch 2 · p 12–13

Book example: IMDB movie reviews come with a star rating, so each review can be labelled positive or negative. That makes it supervised NLP. Ch 11 · p 190–191

Trask's fill-in-the-blank network trains on plain text with no human labels at all: it hides a word and learns to predict it. The text supplies its own labels. Ch 11 · p 201

Not in Trask

This trick is called self-supervised learning, and it's how LLMs are pretrained on huge amounts of unlabelled text.

SU5–7 · 5.2

Understand the nature of data and how different techniques apply to unlabelled data than to labelled data

5.2Trask+
Nd

Data decides the technique

What you can do depends on what you have. With labels you can learn to predict them. Without labels you can only find structure (groups, main directions of variation, outliers) or invent labels from the data itself.

Ch 2 · p 12–13, 17Ch 10 · p 178Ch 12 · p 210

Supervised learning turns what you know into what you want to know. Unsupervised learning finds groups that you then have to interpret; the algorithm never tells you what a cluster means. Ch 2 · p 12–13

The two work together: unsupervised learning is often done to help build a better supervised model. Ch 2 · p 12

The type of data matters too: images have spatial structure, which suits convolutions; text is a variable-length sequence of words, which suits embeddings and recurrent layers. Ch 10 · p 178 Ch 12 · p 210

SU5–7 · 5.3

Perform clustering operations on unlabelled data

5.3Trask+
Cu

Clustering

Clustering puts similar unlabelled points into groups. k-means is the classic: pick k centres, assign every point to the nearest one, move each centre to the middle of its points, repeat.

Ch 2 · p 13, 17Ch 11 · p 199–203

Clustering turns a list of datapoints into a list of cluster labels (1–10 for 10 clusters). The labels are just numbers; you work out what each group means: puppies and kittens = 'cute', pizza and burgers = 'delicious'. Ch 2 · p 13

An unsupervised parametric model outputs, for each group, the probability that a datapoint belongs to it (e.g. 94% group 1, 1% group 2, 5% group 3). Ch 2 · p 17

Clusters also appear inside neural networks. After training on movie reviews, similar words get similar embedding vectors, and you can list a word's nearest neighbours ('terrible' → 'dull', 'boring', 'disappointing'). What the words cluster by depends on the training task. Ch 11 · p 199–203

Not in Trask

k-means, step by step

  1. Choose k, the number of clusters.
  2. Place k centres (centroids), e.g. at random points.
  3. Assign: each point joins its nearest centre.
  4. Update: move each centre to the mean of its points.
  5. Repeat steps 3–4 until nothing changes.
from sklearn.datasets import make_blobs
from sklearn.preprocessing import StandardScaler
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score

X, _ = make_blobs(n_samples=300, centers=3, random_state=42)    # throw the labels away
X = StandardScaler().fit_transform(X)                           # distances need equal scales
for k in range(2, 7):                                           # which k fits best?
    km = KMeans(n_clusters=k, n_init=10, random_state=0).fit(X)
    print(k, round(km.inertia_, 1), round(silhouette_score(X, km.labels_), 3))
labels = KMeans(n_clusters=3, n_init=10, random_state=0).fit_predict(X)

Choosing k: plot the inertia (total squared distance to the centres) for k = 1…10 and look for the 'elbow', or pick the k with the highest silhouette score. Other methods: DBSCAN finds clusters of any shape and marks outliers as noise; hierarchical clustering builds a tree of merges.

SU5–7 · 5.4

Understand and use tools that use semi-supervised learning

5.4Extra
Ss

Semi-supervised learning

Use a small labelled set together with a large unlabelled one. The model labels the unlabelled data itself (self-training) or spreads labels to similar points (label propagation).

Ch 2 · p 12 (background only)

Trask doesn't cover semi-supervised learning. He does note that unsupervised learning is usually done to help supervised learning, which is the idea semi-supervised methods build on. Ch 2 · p 12

Not in Trask

Labelling is slow and costly; unlabelled data is cheap. Semi-supervised learning sits between supervised and unsupervised, and assumes that points close together (or in the same cluster) probably share a label.

Self-training (pseudo-labelling)

  1. Train a model on the labelled data.
  2. Predict the unlabelled data.
  3. Keep the predictions it's very confident about (e.g. ≥ 90%) as pseudo-labels.
  4. Retrain on labelled + pseudo-labelled data, and repeat.

Label propagation and spreading

Connect similar points in a graph; the known labels spread along the connections to their neighbours, like ink in water.

import numpy as np
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.semi_supervised import SelfTrainingClassifier, LabelSpreading
from sklearn.svm import SVC

X, y = load_digits(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=0)
rng = np.random.RandomState(0)
y_partial = y_train.copy()
y_partial[rng.rand(len(y_partial)) < 0.9] = -1      # hide 90% of the labels (-1 = unlabelled)

self_train = SelfTrainingClassifier(SVC(probability=True, gamma=0.001), threshold=0.9)
self_train.fit(X_train, y_partial)
print("self-training  ", self_train.score(X_test, y_test))

spread = LabelSpreading(kernel="knn", n_neighbors=7).fit(X_train, y_partial)
print("label spreading", spread.score(X_test, y_test))

SU5–7 · 5.5

Understand and use transfer learning to apply a model trained in one domain to a different domain

5.5Trask+
Tl

Transfer learning

Reuse what a model learned on one task as the starting point for another: keep (freeze) the early layers, replace and retrain the last ones, then optionally fine-tune everything with a small learning rate.

Ch 3 · p 26Ch 5 · p 88Ch 10 · p 185Ch 11 · p 194, 203

Trask doesn't use the term, but the ingredients are in the book:

  • Knowledge lives in the weights, so weights can be copied into another network. Ch 3 · p 26
  • A weight can be frozen (not updated) while the rest keep learning. Ch 5 · p 88
  • Early CNN layers learn general features (lines, edges, corners) that any image task needs. Ch 10 · p 185
  • Word embeddings learned on one task capture meaning that can be reused, and what they capture depends on the task they were trained on. Ch 11 · p 194, 203
Not in Trask

Hatched = frozen (copied, not trained). Plain = retrained or fine-tuned. Highlighted = new output layer.

  1. Start from a model pretrained on a big dataset (ImageNet photos; web text for LLMs).
  2. Remove its output layer and add a new one for your classes.
  3. Feature extraction: freeze the pretrained layers and train only the new head.
  4. Fine-tuning: then unfreeze some or all layers and train with a small learning rate, so the useful features are adjusted rather than wiped out.

Why bother: you need far less data and compute, and usually get better accuracy than training from scratch on a small dataset. Domain shift: the further the new domain is from the original (everyday photos → spectrograms), the more layers you may need to retrain.

import timm
# EfficientNetV2-S pretrained on ImageNet; timm swaps the 1000-class head for a new 22-class one
model = timm.create_model("tf_efficientnetv2_s", pretrained=True, num_classes=22)
# fine-tune with a small learning rate (1e-4): a large one washes out the pretrained features

This is exactly what our SU4 group project does in models/transfer_cnn.py, next to a CNN trained from scratch for comparison. For LLMs it's the same idea: a model pretrained on general text is fine-tuned on one domain (see 5.8).

How LLMs work

An LLM turns text into tokens, tokens into embedding vectors, mixes them through stacked transformer layers (attention + feed-forward), and ends with a softmax over the vocabulary to predict the next token. Repeat to generate text.

What changed: attention and transformers

RNNs read one token at a time and squeeze everything into one hidden state, which forgets over long texts and can't be parallelised. A transformer (2017) drops recurrence. In each self-attention layer, every token makes a query, a key and a value vector; it compares its query with every token's key, turns the scores into weights with softmax, and takes a weighted sum of the values. That's the SU2 weighted sum again, with the weights worked out on the fly.

Attention(Q, K, V) = softmax(Q · Kᵀ / √d) · V
  • Context window: how many tokens the model can attend to at once. Ollama loads models with 4,096 tokens by default; agents need far more (see my local-LLM notes).
  • Positional information is added to the embeddings so that word order matters.
  • Parameters are the weights: '12B' means 12 billion. Quantisation (e.g. Q4_K_M) stores them in about 4 bits each, so a 12B model fits in 12 GB of VRAM.
  • Sampling: temperature and top-p control how the next token is picked from the softmax probabilities.
  • Speculative decoding: a small draft model proposes tokens and the big model checks them in one pass. That's why Gemma 4 12B ran at 172 tokens/s on my GPU.
  • Sliding-window attention: some layers only look at the most recent tokens, to save memory.

Our SU4 group project also has a Swin transformer: attention applied to image patches instead of words.

Use Large Language Models effectively as they exist already

5.7Extra
Us

Using LLMs well

Pick a model that fits your hardware and task, give it clear instructions and the right context, let it use tools, and always check its output.

not in the book (2019)

Not covered in Trask: the book predates modern LLMs. This section is based on my own setup and general practice.

Not in Trask

Picking a model

  • The model plus its context should fit fully in VRAM; spilling into system RAM is much slower.
  • Quantised versions (Q4, Q5) trade a little quality for a lot of memory.
  • Specialised models (coding, vision, reasoning) beat general ones of the same size at their task.

Prompting

  • Be specific: role, task, constraints, output format, an example.
  • Give it the context it needs (files, docs) instead of hoping it knows.
  • Break big tasks into steps, and ask for a plan first.
  • Use low temperature for facts and code, higher for brainstorming.

Beyond prompting

Know the limits

LLMs can be confidently wrong (hallucination), have a knowledge cutoff, and lose anything beyond their context window. Verify facts, run the code, and review every diff.

Fine-tune a Large Language Model to a specific domain

5.8Extra
Ft

Fine-tuning an LLM

Keep training a pretrained LLM on examples from your domain so its weights shift towards your task. LoRA trains small adapter matrices instead of all the weights, which makes it possible on one consumer GPU (e.g. with Unsloth).

Ch 4 · p 56–76Ch 5 · p 88Ch 8 · p 150–152 (background)

Fine-tuning is chapter 4's gradient descent applied to a pretrained network: predict, compare with the example answer, nudge the weights. Ch 4 · p 56–76 LoRA's frozen base weights echo the frozen-weight experiment. Ch 5 · p 88 And the book's warnings still apply: a small dataset trained for too long gets memorised, so keep a validation set. Ch 8 · p 150–152

Not in Trask

Workflow

  1. Goal: what should the model do better? (answer in my project's style, know ITRI626 terms, use my tools correctly)
  2. Dataset: hundreds to a few thousand instruction → response pairs in the model's chat format; hold back ~10% for validation.
  3. Base model that fits the GPU (a 4–9B model for QLoRA on 12 GB).
  4. Train LoRA adapters for 1–3 epochs, watching training and validation loss.
  5. Evaluate against the base model on held-out questions.
  6. Export: merge the adapters, convert to GGUF, load into Ollama with a Modelfile.
from unsloth import FastLanguageModel
from datasets import load_dataset
from trl import SFTTrainer, SFTConfig

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Qwen3-4B",        # any base model that fits in 12 GB
    max_seq_length=2048,
    load_in_4bit=True,                    # QLoRA: 4-bit base model
)
model = FastLanguageModel.get_peft_model(
    model, r=16, lora_alpha=16,           # LoRA rank and scaling
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
)
dataset = load_dataset("json", data_files="my_domain.jsonl", split="train")   # one {"text": ...} per line
trainer = SFTTrainer(
    model=model, tokenizer=tokenizer, train_dataset=dataset,
    args=SFTConfig(per_device_train_batch_size=2, gradient_accumulation_steps=4,
                   num_train_epochs=1, learning_rate=2e-4, output_dir="outputs"),
)
trainer.train()
model.save_pretrained_gguf("my-model", tokenizer, quantization_method="q4_k_m")   # for Ollama
